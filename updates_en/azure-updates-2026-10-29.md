**Azure Update Report: Public Preview – Cross Tenant Restore with Azure Backup**

**Background and Purpose of the Update:**  
The Cross-Tenant Restore (CTR) feature in Azure Backup addresses the increasing need for organizations to enhance their cyber resilience and disaster recovery strategies. Traditionally, Azure VM backups could only be restored within the same Azure tenant, limiting recovery options in the event of tenant-level compromise or ransomware attacks. CTR enables organizations to establish an independent recovery path by allowing Azure VM backups to be restored into a separate Azure tenant, thus providing an additional layer of protection and flexibility.

**Specific Features and Detailed Changes:**  
With this update, Azure Backup introduces the capability to restore VM backups across Azure tenants. This means that a backup copy taken in one tenant can be used to recover resources in another tenant without requiring custom solutions or manual intervention. The feature leverages the existing backup copy, ensuring that organizations do not need to create or maintain duplicate backup sets for cross-tenant recovery purposes.

**Technical Mechanisms and Implementation Methods:**  
CTR operates by utilizing Azure Backup’s secure backup storage and recovery mechanisms. When a restore operation is initiated, the backup copy is accessed and restored directly into a different Azure tenant. The process is managed through Azure Backup’s interface, and does not require custom scripting or third-party tools. The mechanism is designed to maintain the integrity and security of the backup data during the cross-tenant restore process, leveraging Azure’s built-in authentication and authorization controls to facilitate secure data transfer and recovery.

**Use Cases and Application Scenarios:**  
- **Cyber Resilience:** Organizations can recover critical workloads to a separate tenant in the event of a security breach or ransomware attack affecting the primary tenant.
- **Disaster Recovery:** Enables restoration of VMs to a secondary tenant as part of a disaster recovery plan, ensuring business continuity.
- **Mergers and Acquisitions:** Facilitates migration of VM backups between tenants during organizational restructuring or mergers.
- **Testing and Validation:** Allows IT teams to restore backups into isolated tenants for testing, validation, or compliance purposes without impacting production environments.

**Important Considerations and Limitations:**  
- CTR is currently available in Public Preview, which may include limitations in terms of supported VM types, regions, or scale.
- The feature relies on the existing backup copy, so organizations must ensure their backup policies and retention settings are appropriately configured.
- Security and access permissions must be managed carefully to allow authorized cross-tenant restore operations.
- There may be restrictions on the types of resources or configurations that can be restored across tenants, depending on Azure Backup’s current capabilities.

**Integration with Related Azure Services:**  
CTR is fully integrated with Azure Backup, leveraging its backup management, storage, and recovery workflows. It complements Azure’s broader security and disaster recovery offerings, such as Azure Site Recovery and Azure Security Center, by providing an additional recovery path. Organizations can use CTR alongside existing backup and recovery strategies to enhance their overall resilience and compliance posture.
