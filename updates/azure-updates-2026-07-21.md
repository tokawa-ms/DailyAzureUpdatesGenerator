### 1. Public Preview: Protect sensitive generative AI telemetry in Application Insights and Microsoft Foundry

**公開日時**: 2026年07月20日 15:09:43 UTC

**情報源**: Azure Updates API

**カテゴリ**: In preview, DevOps, Management and governance, Azure Monitor, Management, Security

**要約**:

【何が更新されたか】  
Azure Monitor Application Insightsにおいて、生成AIのテレメトリデータが専用のGenAIContentテーブル（Log AnalyticsではAppGenAIContent）に保存されるようになりました。  

【主な変更点や新機能】  
生成AI関連のコンテンツを分離して保存することで、機密性の高いAIテレメトリに対して新たなアクセス制御を適用できるようになりました。これにより、AIの入力や出力などのセンシティブなデータの管理が強化されます。  

【影響を受ける対象】  
Application InsightsやMicrosoft Foundryを利用して生成AIのテレメトリを収集・分析している技術者や開発者が対象です。特に、AIサービスの監視やログ管理を行っている方に影響があります。  

【注意点】  
新しいテーブルへのデータ保存やアクセス制御の導入により、既存の監視・分析フローや権限設定の見直しが必要となる場合があります。アクセス権限の設定やデータの取り扱いに注意してください。

**詳細**:

本アップデートは、Azure Monitor Application Insightsにおいて生成AI（Generative AI）によるテレメトリデータの取り扱いを強化するためのものです。これまでApplication Insightsはアプリケーションのパフォーマンスや利用状況を監視するためのテレメトリデータを収集・保存してきましたが、生成AIを活用するアプリケーションの増加に伴い、AIが生成したコンテンツやプロンプトなど、よりセンシティブな情報がテレメトリとして記録されるケースが増えています。このアップデートの目的は、そうしたセンシティブな生成AI関連データをより安全かつ適切に管理することにあります。

具体的な変更点として、Application Insightsは生成AIコンテンツを専用のGenAIContentテーブル（Log Analytics上ではAppGenAIContentテーブル）に保存するようになりました。これにより、従来のテレメトリデータとは分離してAI関連のデータを管理できるようになります。さらに、この専用テーブルに対して新たなアクセス制御機能が提供され、機密性の高いAIテレメトリへのアクセスを厳格に管理することが可能となります。これにより、組織内での権限分離や、コンプライアンス要件への対応が容易になります。

技術的な仕組みとしては、Application Insightsが収集した生成AI関連のテレメトリデータを自動的にGenAIContentテーブルに格納し、Log Analyticsワークスペース上でもAppGenAIContentとして参照できるようになっています。アクセス制御はAzureのロールベースアクセス制御（RBAC）やLog Analyticsのクエリアクセス権限と連携して動作し、特定のユーザーやグループのみがAIテレメトリにアクセスできるように設定できます。

活用シナリオとしては、生成AIを組み込んだWebアプリケーションやチャットボット、コンテンツ生成サービスなどで、ユーザーの入力プロンプトやAIが生成した応答内容を監査・分析する場合に有効です。例えば、AIの応答品質のモニタリングや不適切な出力の検出、ユーザー行動の分析などに活用できますが、同時に個人情報や機密情報が含まれる可能性があるため、厳格なアクセス管理が求められます。

注意点として、GenAIContentテーブルに保存されたデータは、従来のテレメトリとは異なる管理が必要となります。アクセス権限の設定や監査ログの取得など、セキュリティポリシーに基づいた運用が不可欠です。また、本機能はパブリックプレビュー段階であるため、運用環境での利用には十分な検証が推奨されます。

関連するAzureサービスとしては、Azure Monitor、Log Analytics、Microsoft Foundryなどが挙げられます。これらのサービスと連携することで、生成AIテレメトリの収集・分析・可視化・監査までを一元的に行うことが可能です。詳細は公式ドキュメントやアップデート情報を参照してください。

**要約**:

- 何が更新されたか  
Azure VPN GatewayでIPv6サポートが一般提供（GA）されました。

- 主な変更点や新機能  
今回のアップデートにより、Azure VPN Gatewayでデュアルスタック構成（IPv4/IPv6）を利用し、VPNトンネル内でIPv6トラフィックを通過させることが可能になりました。標準パブリックIPアドレスを使用する全ての本番用SKUゲートウェイでIPv6がサポートされます。IPv6トラフィックは、サイト間VPNおよびポイント対サイトVPNの両方で構成できます。

- 影響を受ける対象  
Azure VPN Gatewayを利用しており、IPv6対応やデュアルスタック構成を必要とする企業や組織が対象です。特に、グローバルなネットワーク要件や将来的なIPv6移行を検討している技術者にとって重要なアップデートです。

- 注意点があれば記載  
IPv6サポートは標準パブリックIPアドレスを利用する本番用SKUゲートウェイのみが対象です。既存のIPv4構成との互換性や、ネットワークセキュリティグループ（NSG）設定など、IPv6導入時の追加設定に注意が必要です。

**詳細**:

本アップデートは、Azure VPN GatewayにおけるIPv6サポートの一般提供開始を示しています。これにより、Azure VPN Gatewayを利用するお客様は、デュアルスタック構成においてVPNトンネルを通じてIPv6のインナートラフィックを流すことが可能となりました。IPv6サポートは、標準パブリックIPアドレスを使用するすべてのプロダクションSKUゲートウェイで利用できます。

本機能の主な目的は、クラウド環境におけるIPv6対応のニーズに応えることです。近年、IoTやモバイルデバイスの増加に伴い、IPv4アドレス枯渇への対応や、グローバルなネットワーク設計の柔軟性向上が求められています。Azure VPN GatewayがIPv6インナートラフィックをサポートすることで、オンプレミス環境や他のクラウドとの間でIPv6アドレス空間を活用したセキュアな通信が実現できます。

技術的には、デュアルスタック構成が可能となっており、IPv4とIPv6の両方のトラフィックを同時にVPNトンネルで転送できます。設定においては、標準パブリックIPアドレスを持つVPN GatewayのプロダクションSKUを選択し、必要に応じてIPv6アドレス空間を持つ仮想ネットワーク（VNet）やサブネットを構成することで、IPv6トラフィックのルーティングが可能です。

活用シナリオとしては、IPv6アドレス空間を持つオンプレミスネットワークとAzure間のVPN接続、またはハイブリッドクラウド環境でのIPv6通信の確立などが挙げられます。これにより、将来的なネットワーク拡張やグローバル展開を見据えた設計が容易になります。

注意点としては、IPv6サポートは標準パブリックIPアドレスを利用するプロダクションSKUゲートウェイに限定されているため、ベーシックSKUやカスタムIP構成では利用できません。また、既存のIPv4環境との互換性や、ネットワークセキュリティグループ（NSG）やルートテーブルの設定にも注意が必要です。

関連するAzureサービスとしては、Azure Virtual NetworkやExpressRouteなどが挙げられますが、本アップデートはVPN Gatewayに特化した機能追加となっています。詳細については公式ドキュメントやアップデート情報を参照してください。
