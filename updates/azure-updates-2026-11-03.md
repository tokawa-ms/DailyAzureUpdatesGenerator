### 1. Public Preview: On-prem NAS share discovery and assessment are now available using Azure Migrate

**公開日時**: 2026年11月02日 19:37:11 UTC
**リンク**: [Public Preview: On-prem NAS share discovery and assessment are now available using Azure Migrate](https://azure.microsoft.com/updates?id=577975)

**アップデートID**: 577975
**情報源**: Azure Updates API

**カテゴリ**: In preview, Management and governance, Migration, Azure Migrate, Features, Services

**要約**:

【何が更新されたか】  
Azure MigrateでオンプレミスのNAS（ネットワークアタッチトストレージ）共有のディスカバリーとアセスメント機能がパブリックプレビューとして利用可能になりました。

【主な変更点や新機能】  
Azure Migrateアプライアンスが、Dell PowerScale（OneFS）やNetApp ONTAPストレージのNAS共有に直接接続し、ストレージのディスカバリーとアセスメントを実施できるようになりました。これにより、NASからAzureへの移行計画を効率的に立てることが可能です。

【影響を受ける対象】  
オンプレミスでDell PowerScale（OneFS）やNetApp ONTAPのNASストレージを利用している企業やパートナーが対象です。これらのストレージからAzureへの移行を検討している技術者にとって重要なアップデートです。

【注意点】  
現時点ではパブリックプレビューの段階ですので、本番環境での利用には慎重な検証が必要です。また、Azure Migrateアプライアンスの導入やNAS共有への接続設定が必要となります。

**詳細**:

Azure Migrateの最新アップデートでは、オンプレミスのNAS（Network-Attached Storage）共有ディスカバリーとアセスメント機能がパブリックプレビューとして提供開始されました。このアップデートの背景には、企業がDell PowerScale（OneFS）やNetApp ONTAPといった主要なNASストレージからAzureへの移行を計画する際、現状のストレージ環境を正確に把握し、移行計画を最適化したいというニーズがあります。従来のAzure Migrateは主にサーバーやVMの移行に焦点を当てていましたが、今回のアップデートによりNASストレージのディスカバリーと評価が可能となり、移行対象の範囲が大きく拡張されました。

具体的な機能として、Azure MigrateアプライアンスがオンプレミスのNASクライアントに直接接続し、NAS共有の構成や使用状況を自動的に検出します。これにより、NAS上のデータ量、アクセス頻度、ストレージ構造などの詳細な情報を収集し、Azureへの移行に必要な前提条件や移行先のストレージサービスの選定に役立てることができます。アセスメント機能では、収集した情報を基に移行の適合性や推奨されるAzureストレージサービス（例：Azure Files、Azure NetApp Filesなど）を提示し、移行計画の策定を支援します。

技術的な仕組みとしては、Azure MigrateアプライアンスがNASプロトコル（SMB/NFSなど）を利用してNAS共有にアクセスし、必要なメタデータや統計情報を収集します。収集されたデータはAzure Migrateのポータル上で可視化され、移行のアセスメントレポートとして出力されます。これにより、技術者は現状のNAS環境を詳細に把握し、移行リスクやコスト、パフォーマンス要件を事前に評価することが可能です。

主な活用シナリオとしては、企業がDell PowerScaleやNetApp ONTAPのNASストレージをAzureに移行する際、事前調査や移行計画の立案にAzure Migrateを利用するケースが挙げられます。例えば、複数のNAS共有を持つ大規模環境で、どの共有をどのAzureストレージサービスに移行すべきかを判断する際に、ディスカバリーとアセスメント機能が有効です。また、パートナー企業が顧客のNAS環境を評価し、最適な移行プランを提案する際にも活用できます。

注意点としては、パブリックプレビュー段階であるため、機能や対応範囲に制限がある場合があります。現時点ではDell PowerScale（OneFS）およびNetApp ONTAPが対象ですが、他のNAS製品や特殊な構成には未対応の可能性があります。また、アプライアンスの導入やネットワーク設定など、事前準備が必要となる場合がありますので、公式ドキュメントやサポート情報を必ず確認してください。

関連するAzureサービスとしては、Azure FilesやAzure NetApp Filesが移行先として想定されており、Azure Migrateでのアセスメント結果を基に、これらのサービスへの移行計画を立てることができます。今回のアップデートにより、Azure Migrateはオンプレミスからクラウドへのストレージ移行を包括的に支援するプラットフォームとして、より実用的な選択肢となっています。

具体的な変更内容としては、Defender for IoTのOTセキュリティコンポーネントの新規提供や機能追加が停止され、既存の機能も2029年10月をもって完全に利用できなくなります。技術的な仕組みとしては、Defender for IoTがOTネットワーク上のプロトコル解析やパケット監視、異常検知などを行っていましたが、これらの機能が廃止対象となります。実装方法としては、オンプレミスのセンサーやクラウド連携によるデータ収集・分析が中心でしたが、今後はこれらの仕組みも利用できなくなります。

**リンク**: [Generally Available: Change from virtual network integration to a private endpoint capable network configuration in Azure Database for PostgreSQL flexible server  ](https://azure.microsoft.com/updates?id=574541)

**情報源**: Azure Updates API

**カテゴリ**: Launched, Databases, Hybrid + multicloud, Azure Database for PostgreSQL, Feature

**要約**:

- 何が更新されたか  
Azure Database for PostgreSQL Flexible Serverにおいて、既存の仮想ネットワーク（VNet）統合サーバーのネットワーク構成を、プライベートエンドポイント対応の構成へ変更できるようになりました。

- 主な変更点や新機能  
これまでVNet統合（委任サブネット）で構成されていたサーバーを、プライベートエンドポイントを利用可能なネットワーク構成へ移行できるようになりました。これにより、より柔軟かつセキュアなネットワーク設計が可能となります。

- 影響を受ける対象  
Azure Database for PostgreSQL Flexible ServerをVNet統合（委任サブネット）で利用している環境が対象です。プライベートエンドポイントによるアクセス制御やセキュリティ強化を検討している技術者にとって重要なアップデートです。

ネットワーク構成の変更に伴い、既存の接続設定やアクセス制御に影響が出る可能性があります。変更前に十分な検証と影響範囲の確認を行うことを推奨します。

**詳細**:

Azure Database for PostgreSQL Flexible Serverにおいて、仮想ネットワーク（VNet）統合サーバーのネットワーク構成を、委任サブネット型からプライベートエンドポイント対応型へ変更できる機能が一般提供されました。このアップデートの背景には、より柔軟なネットワーク設計とセキュリティ強化へのニーズがあります。従来はVNet統合サーバーを委任サブネットに配置することで、ネットワークの分離や管理が可能でしたが、プライベートエンドポイントを活用した構成への変更が容易ではありませんでした。

今回の変更により、既存の委任サブネット型VNet統合サーバーを、プライベートエンドポイント対応ネットワーク構成へ移行できるようになりました。これにより、Azure Database for PostgreSQL Flexible Serverへのアクセスを、Azure Private Linkを利用してプライベートIP経由で行うことが可能となり、インターネット経由のアクセスを遮断しつつ、セキュアな通信を実現できます。技術的には、サーバーのネットワーク設定を変更することで、プライベートエンドポイントの作成と接続が可能となり、既存のVNet統合環境からの移行もサポートされています。

この機能は、金融や医療など高いセキュリティ要件が求められるシステムや、複数のAzureサービス間で安全にデータベース通信を行いたい場合に有効です。例えば、Azure App ServiceやAzure Functionsなどのアプリケーションが、同一VNet内からプライベートエンドポイント経由でPostgreSQL Flexible Serverに接続するシナリオが想定されます。

注意点として、ネットワーク構成の変更には適切な権限と計画が必要です。既存の委任サブネット型からプライベートエンドポイント対応型への移行時には、接続元アプリケーションやサービスのネットワーク設定も見直す必要があります。また、プライベートエンドポイントの利用には、DNS設定やVNet内のルーティングなど追加の構成が求められる場合があります。

関連するAzureサービスとしては、Azure Private LinkやAzure Virtual Network、Azure DNSなどが挙げられます。これらのサービスと連携することで、より高度なネットワーク分離やセキュリティ対策を実現できます。今回のアップデートは、Azure Database for PostgreSQL Flexible Serverのネットワーク構成管理の柔軟性とセキュリティを大幅に向上させるものです。

### 4. Retirement: Azure Fluid Relay

**公開日時**: 2026年11月02日 19:01:41 UTC
**リンク**: [Retirement: Azure Fluid Relay](https://azure.microsoft.com/updates?id=570498)

**アップデートID**: 570498
**情報源**: Azure Updates API

**カテゴリ**: Web, Azure Fluid Relay, Retirements

**要約**:

【何が更新されたか】  
Azure Fluid Relayのサービスが2027年2月2日に廃止されることが発表されました。

【主な変更点や新機能】  
今回のアップデートでは新機能の追加はありません。Azure Fluid Relayの提供終了が主な変更点です。なお、Fluid Framework自体は引き続きオープンソースとして利用可能です。

【影響を受ける対象】  
Azure Fluid Relayを利用しているアプリケーションやワークロードが影響を受けます。サービス終了後も依存し続ける場合、システムの動作に支障が生じる可能性があります。

【注意点】  
2027年2月2日以降、Azure Fluid Relayは利用できなくなります。既存のワークロードはサービス終了までに移行や代替手段の検討が必要です。Fluid Frameworkのオープンソース版への移行や他のリアルタイムコラボレーションサービスの利用を早期に計画してください。

**詳細**:

2027年2月2日をもって、Azure Fluid Relayは廃止されます。この日以降、Azure Fluid Relayは利用不可となり、同サービスに依存するワークロードはサービス停止や動作不良などの影響を受ける可能性があります。Fluid Framework自体は引き続きオープンソースとして利用可能ですが、Azure Fluid Relayのマネージドサービスとしての提供は終了します。

Azure Fluid Relayは、リアルタイムの共同編集やデータ同期を実現するためのバックエンドサービスとして設計されていました。Fluid Frameworkを利用するアプリケーションにおいて、複数のクライアント間でデータの同期や状態の共有を効率的に行うためのリレーサーバーの役割を担っていました。これにより、ドキュメントやデータ構造のリアルタイムな共同編集が可能となり、コラボレーションアプリケーションの開発を容易にしていました。

Fluid Framework自体は、分散型データ構造（Distributed Data Structures）を活用し、クライアント間での変更内容を効率的に伝播させる仕組みを持っています。Azure Fluid Relayは、このフレームワークの通信基盤として機能し、クライアントからの変更イベントを中継し、全クライアントに対してリアルタイムで同期を行う役割を果たしていました。実装面では、Azureのマネージドサービスとして提供されることで、スケーラビリティや可用性、セキュリティの確保が容易になっていました。

主な活用シナリオとしては、複数ユーザーによるリアルタイムドキュメント編集、共同作業ツール、ライブデータダッシュボードなどが挙げられます。これらのアプリケーションでは、ユーザー間の即時同期が求められるため、Fluid Relayのようなサービスが不可欠でした。

廃止に伴い、既存のAzure Fluid Relay利用者は、サービス停止日までに移行計画を策定し、必要に応じてFluid Frameworkのオープンソース版を利用した独自のリレーサーバー構築や、他のリアルタイム同期ソリューションへの移行を検討する必要があります。サービス終了後も依存を続ける場合、アプリケーションの動作に重大な影響が生じるため、早期の対応が推奨されます。

Azure Fluid Relayは、他のAzureサービスとの直接的な連携機能については明記されていませんが、一般的にAzure上のアプリケーションやサービスと組み合わせて利用されていました。今後は、Fluid Frameworkのオープンソース実装を活用しつつ、Azureの他のサービスとの連携方法を再検討する必要があります。

詳細は公式アップデート情報（https://azure.microsoft.com/updates?id=570498）をご参照ください。

### 5. Generally Available: Azure Storage Actions adds automatic task updates, execution controls, and case-sensitive matching

**公開日時**: 2026年11月02日 18:34:01 UTC
**リンク**: [Generally Available: Azure Storage Actions adds automatic task updates, execution controls, and case-sensitive matching](https://azure.microsoft.com/updates?id=578628)

**アップデートID**: 578628
**情報源**: Azure Updates API

**カテゴリ**: Launched, Storage, Analytics, Azure Blob Storage, Azure Data Lake Storage, Azure Storage Actions, Services, Feature

**要約**:

【何が更新されたか】  
Azure Storage Actionsが一般提供（GA）となり、タスク管理や自動データ操作の制御機能が強化されました。

【主な変更点や新機能】  
1. タスク定義の自動更新伝播：ストレージアクションのタスク定義を更新すると、その変更が自動的に関連タスクへ反映されます。  
2. 実行制御機能：タスクの実行タイミングや条件を細かく管理できるようになりました。  
3. 大文字・小文字の区別によるマッチング：タスクの条件設定時に、大文字・小文字を区別したマッチングが可能となりました。

【影響を受ける対象】  
Azure Blob StorageおよびAzure Data Lake Storageを利用しているユーザーや、Storage Actionsを活用して自動化タスクを管理している技術者が対象です。

【注意点】  
新機能を利用する際は、タスク定義の変更が自動的に伝播されるため、意図しない影響が出ないよう事前に確認してください。また、大文字・小文字の区別設定により、条件式の挙動が変わる場合がありますので注意が必要です。

**詳細**:

Azure Storage Actionsは、Azure Blob StorageおよびData Lake Storageにおける自動データ操作の管理を簡素化し、より高度な制御を提供するために、3つの主要な機能強化を一般提供（GA）としてリリースしました。今回のアップデートの背景には、ストレージ上で実行されるタスクの定義や管理を効率化し、運用負荷の軽減と自動化の精度向上を目指す目的があります。

具体的な変更点として、まず「タスク定義の自動伝播」が挙げられます。これは、ストレージアクションのタスク定義を更新した際、関連するタスクにその変更が自動的に反映される仕組みです。従来は、タスク定義の更新後に手動で各タスクへ適用する必要がありましたが、この機能により管理者の作業負担が大幅に軽減されます。技術的には、タスク定義のバージョン管理や依存関係の自動解決がバックグラウンドで行われるため、運用中のタスクに対して一貫性のある更新が保証されます。

次に、「実行制御機能の追加」が実装されています。これにより、タスクの実行タイミングや条件を細かく設定できるようになりました。例えば、特定の時間帯やイベント発生時のみタスクを実行するなど、運用ポリシーに合わせた柔軟な制御が可能です。これらの制御は、Azure Storage Actionsの管理画面やAPIを通じて設定でき、既存の自動化ワークフローとシームレスに連携します。

さらに、「大文字・小文字の区別によるマッチング機能」が追加されました。ストレージ上のオブジェクト名やパスのマッチング時に、ケースセンシティブ（大文字・小文字を区別）での判定が可能となり、より厳密な条件指定が行えます。これにより、ファイル名やディレクトリ構造の管理が複雑な環境でも、意図した対象のみを確実に操作することができます。

これらの機能は、Azure Blob StorageやData Lake Storageを利用したデータパイプラインやETL処理、バックアップ、アーカイブなどのシナリオで特に有効です。例えば、定期的なログファイルの整理や、特定条件下でのデータ移動・削除など、運用効率と精度が求められる場面で活用できます。また、Azure Logic AppsやAzure Functionsなどの他のAzureサービスと連携することで、より高度な自動化ワークフローの構築が可能です。

注意点として、タスク定義の自動更新は一部の複雑な依存関係や、外部システムとの連携時に予期せぬ動作を引き起こす可能性があるため、事前に十分な検証が必要です。また、ケースセンシティブなマッチングを利用する際は、ストレージアカウントの設定や既存データの命名規則との整合性に注意してください。

以上のアップデートにより、Azure Storage Actionsはストレージ運用の自動化と制御性を大幅に向上させ、Azure上でのデータ管理をより効率的かつ安全に実現できるようになりました。
