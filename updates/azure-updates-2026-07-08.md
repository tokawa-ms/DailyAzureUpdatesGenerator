### 1. Public Preview: Exceptions in WAF for Azure Application Gateway and Azure Front Door

**公開日時**: 2026年07月07日 17:42:50 UTC
**リンク**: [Public Preview: Exceptions in WAF for Azure Application Gateway and Azure Front Door](https://azure.microsoft.com/updates?id=567218)

**アップデートID**: 567218
**情報源**: Azure Updates API

**カテゴリ**: In preview, Networking, Security, Application Gateway, Azure Front Door, Web Application Firewall, Features, Services

**要約**:

【何が更新されたか】  
Azure Application GatewayおよびAzure Front DoorのWeb Application Firewall（WAF）において、「Exceptions（例外）」機能がパブリックプレビューとして提供開始されました。

【主な変更点や新機能】  
これまでWAFの「Exclusions（除外）」機能では特定のフィールドや値を除外することで誤検知（False Positive）を減らしていましたが、新たに「Exceptions」機能が追加されました。これにより、特定のリクエストや条件に対してWAFルールの適用を柔軟に制御できるようになります。安全なリクエストが誤ってブロックされる場合に、より細かく例外設定を行うことが可能です。

【影響を受ける対象】  
Azure Application GatewayおよびAzure Front Doorを利用している環境でWAFを導入している技術者や運用担当者が対象となります。特に、WAFによる誤検知や業務アプリケーションの正常なリクエストがブロックされて困っている場合に有用です。

【注意点】  
本機能はパブリックプレビュー段階のため、本番環境での利用には慎重な検証が必要です。今後の正式リリースに向けて仕様や挙動が変更される可能性があります。利用時はMicrosoftの公式ドキュメントやサポート情報を参照してください。

**詳細**:

本アップデートは、「Azure Application Gateway」および「Azure Front Door」におけるWeb Application Firewall（WAF）の例外設定機能のパブリックプレビュー開始に関するものです。WAFは、SQLインジェクションやクロスサイトスクリプティング（XSS）などの一般的なWebアプリケーション攻撃からアプリケーションを保護するためのサービスです。しかし、WAFのルールセットは時として、実際には安全でアプリケーションにとって正当なリクエストまで誤検知し、ブロックしてしまうことがあります。これを「フォールスポジティブ（偽陽性）」と呼びます。

従来からWAFでは、特定のリクエスト属性やパラメータを除外する「除外ルール」を設定することで、こうした偽陽性を低減する手法が提供されてきました。今回のアップデートでは、これに加えて「例外（Exceptions）」の設定が可能となり、さらに柔軟かつ詳細な制御が実現されます。例外設定により、特定の条件に合致するリクエストやパターンをWAFの検査対象から除外することができます。たとえば、特定のIPアドレス、HTTPヘッダー、クエリパラメータ、パスなどを条件として指定し、これらに該当するリクエストのみWAFルールの適用を除外することが可能です。

技術的な実装方法としては、Azure PortalやARMテンプレート、Azure CLIなどを用いて、WAFポリシー内に例外ルールを定義します。これにより、運用中のアプリケーションで発生する特定の誤検知に対して、迅速かつピンポイントで例外対応が可能となります。たとえば、サードパーティ製品との連携や、特定のAPIエンドポイントでのみ発生する偽陽性を個別に除外するシナリオなどで有効です。

例外設定の活用により、WAFによるセキュリティを維持しつつ、アプリケーションの可用性やユーザー体験を損なうことなく運用できます。特に、複数のアプリケーションや環境を一元的に管理する場合、きめ細かな例外設定は大きな利点となります。

一方、例外設定を過度に適用すると、本来ブロックすべき攻撃を許容してしまうリスクがあるため、設定時には十分な検証と運用ポリシーの策定が必要です。また、本機能はパブリックプレビュー段階であるため、本番環境での利用には注意が必要です。正式リリース前のため、サポートや機能変更の可能性も考慮する必要があります。

本機能はAzure Application GatewayおよびAzure Front DoorのWAFポリシーと連携して動作します。これらのサービスを利用している場合、既存のWAFポリシーに例外ルールを追加することで、柔軟なセキュリティ運用が実現できます。詳細については公式ドキュメントやアップデート情報を参照してください。

### 2. Public Preview: Azure Chaos Studio Workspaces and Scenarios

**公開日時**: 2026年07月07日 17:40:32 UTC
**リンク**: [Public Preview: Azure Chaos Studio Workspaces and Scenarios](https://azure.microsoft.com/updates?id=567184)

**アップデートID**: 567184
**情報源**: Azure Updates API

**カテゴリ**: In preview, Analytics, Management and governance, Azure Chaos Studio, Features, Services, Feature

**要約**:

【何が更新されたか】  
Azure Chaos Studioに「Workspaces」と「Scenarios」機能が追加され、パブリックプレビューとして提供開始されました。

【主な変更点や新機能】  
Workspacesは、アプリケーションのスコープ（サブスクリプション、リソースグループ、サービスグループ）単位で障害注入テストを管理できる新しい仕組みです。Scenariosは、実際の障害発生時の挙動を検証するためのテストケースを簡単に作成・実行できる機能です。これにより、従来よりも迅速かつアプリケーション中心で障害耐性の検証が可能となります。

【影響を受ける対象】  
Azure Chaos Studioを利用する技術者や、アプリケーションの可用性・耐障害性を検証したい開発者、運用担当者が対象となります。特に複数リソースをまとめてテストしたい場合に有効です。

【注意点】  
本機能はパブリックプレビュー段階のため、本番環境での利用やサポート範囲に制限がある可能性があります。利用時は公式ドキュメントやサポート情報を確認してください。

**詳細**:

Azure Chaos Studioにおいて、WorkspacesとScenariosの機能がパブリックプレビューとして提供開始されました。このアップデートの背景には、従来の障害注入テストがリソース単位で行われていたため、アプリケーション全体の耐障害性検証が効率的に実施できないという課題があります。今回のアップデートは、より迅速かつアプリケーション中心の障害耐性検証を実現することを目的としています。

具体的な機能として、Workspacesはアプリケーションのスコープ（サブスクリプション、リソースグループ、サービスグループなど）に対して設定でき、対象範囲を明確に指定することが可能です。これにより、複数のリソースやサービスをまとめて管理し、障害シナリオの適用範囲を柔軟に定義できます。Scenariosは、実際の障害発生時の挙動を模擬するためのテストケースを作成・管理する機能であり、アプリケーション全体がどのように動作するかを体系的に検証できます。

技術的な仕組みとしては、Workspacesを作成し、その中でScenariosを定義することで、障害注入の対象や条件を細かく設定できます。例えば、特定のリソースグループに対してネットワーク障害やCPU負荷などの障害を発生させるシナリオを作成し、実際の運用環境に近い形で耐障害性を評価することが可能です。これらの設定はAzure PortalやAPIを通じて管理でき、既存のChaos Studioの障害注入機能と連携して動作します。

活用シナリオとしては、ミッションクリティカルなアプリケーションの運用前検証や、定期的な障害耐性テスト、複数サービスが連携するシステムの統合テストなどが挙げられます。Workspacesを活用することで、複数のリソースやサービスを一括で管理し、シナリオごとに異なる障害パターンを適用することができるため、現実的な障害発生時の対応力を高めることができます。

注意点としては、パブリックプレビュー段階であるため、機能や仕様が今後変更される可能性があること、また一部のAzureリソースやサービスに対しては対応範囲が限定されている場合があることが挙げられます。運用環境での利用に際しては、公式ドキュメントやサポート情報を確認し、最新の対応状況を把握することが重要です。

関連するAzureサービスとの連携については、Chaos Studio自体がAzure MonitorやApplication Insightsなどの監視サービスと組み合わせて利用されることが多く、障害注入後の挙動やメトリックの収集・分析を効率的に行うことができます。これにより、障害時のアプリケーションの動作や復旧プロセスを定量的に評価し、改善につなげることが可能です。

### 3. Public Preview: Export historical data from Log Analytics workspace with Export jobs 

**公開日時**: 2026年07月07日 17:37:55 UTC
**リンク**: [Public Preview: Export historical data from Log Analytics workspace with Export jobs ](https://azure.microsoft.com/updates?id=566591)

**アップデートID**: 566591
**情報源**: Azure Updates API

**カテゴリ**: In preview, DevOps, Management and governance, Azure Monitor, Features, Services

**要約**:

- 何が更新されたか  
Log Analytics ワークスペースから過去のデータをエクスポートできる「Export jobs」機能がパブリックプレビューとして提供開始されました。

- 主な変更点や新機能  
指定したクエリと期間に基づいて、必要な履歴データのみをAzure Storageアカウントへエクスポートできます。これにより、不要なデータを除外し、外部システムへのデータ移行や長期保存が容易になります。

- 影響を受ける対象  
Log Analytics ワークスペースを利用しているユーザーや、監査・分析・バックアップなどで履歴データのエクスポートが必要な技術者が対象です。

- 注意点  
本機能はパブリックプレビュー段階のため、本番環境での利用には注意が必要です。また、エクスポートにはクエリと期間の指定が必須となります。利用には適切なAzure Storageアカウントの準備が必要です。

**詳細**:

本アップデートは、Log Analyticsワークスペースから履歴データをAzure Storageアカウントへエクスポートする機能「Log Analytics Export job」のパブリックプレビュー提供に関するものです。背景として、Log Analyticsワークスペースには大量の監視データやログが蓄積されるため、必要なデータのみを抽出し、外部システムやアーカイブ先へ効率的に移動するニーズが高まっています。このアップデートは、指定したクエリと時間範囲に基づいて履歴データを抽出し、Azure Storageアカウントに保存することを可能にすることで、データの管理や活用の柔軟性を向上させることを目的としています。

具体的な機能としては、ユーザーがLog Analyticsワークスペース内のデータに対してKusto Query Language（KQL）によるクエリを指定し、さらにエクスポートする期間を選択することで、必要なデータのみを抽出できます。エクスポートされたデータはAzure Storageアカウントに保存され、外部システムへの転送や長期保存、分析基盤へのインポートなど多様な用途に活用できます。これにより、全データの一括移動ではなく、必要なデータのみを効率的に取り出すことが可能となります。

技術的な仕組みとしては、Log Analytics Export jobはAzureポータルやAPIを通じてジョブを作成し、指定したクエリと時間範囲に従ってデータを抽出します。抽出されたデータはAzure StorageアカウントのBlobストレージなどに保存され、後続の処理や連携が容易になります。ジョブの管理や進捗状況の確認もAzureポータル上で行うことができます。

活用シナリオとしては、監査やコンプライアンス対応のために特定期間のログを外部ストレージに保存するケースや、データウェアハウスやビッグデータ分析基盤へのデータ移行、障害解析や運用改善のために必要なログのみを抽出して社内システムに連携するケースが想定されます。これにより、従来の手動によるデータ抽出や全データの一括移動に比べて、効率的かつ柔軟な運用が実現できます。

注意点としては、パブリックプレビュー段階であるため、機能や制限事項が今後変更される可能性があること、またエクスポートジョブの実行にはAzure Storageアカウントの事前準備や適切な権限設定が必要であることが挙げられます。さらに、エクスポート対象となるデータ量やジョブの実行時間、コストについても事前に確認することが推奨されます。

関連するAzureサービスとしては、Log Analyticsワークスペース、Azure Storageアカウント、Azure Monitor、Kusto Query Language（KQL）などが密接に連携します。これらのサービスを組み合わせることで、監視データの効率的な管理、分析、外部連携が実現できます。

### 4. Generally Available: Network Security Perimeter support for Azure Event Hubs

**公開日時**: 2026年07月07日 17:35:19 UTC
**リンク**: [Generally Available: Network Security Perimeter support for Azure Event Hubs](https://azure.microsoft.com/updates?id=567203)

**アップデートID**: 567203
**情報源**: Azure Updates API

**カテゴリ**: Launched, Analytics, Event Hubs, Features, Security, Services

**要約**:

【何が更新されたか】  
Azure Event HubsがNetwork Security Perimeter（NSP）に対応し、一般提供（GA）となりました。

【主な変更点や新機能】  
NSPを利用することで、Event HubsなどのPaaSリソースに対して論理的なネットワーク隔離境界を設定できるようになりました。これにより、パブリックネットワーク経由のアクセスをNSPベースのアクセスルールで制御することが可能です。従来のIPベースの制御に加え、より柔軟かつセキュアなアクセス管理が実現します。

【影響を受ける対象】  
Azure Event Hubsを利用している組織や開発者が対象となります。特に、セキュリティ要件が厳しい環境や、ネットワーク隔離を重視するシステムにおいて有効です。

【注意点】  
NSPの導入により、既存のアクセス設定やネットワーク構成に影響が出る場合があります。導入前にアクセスルールやネットワーク設計を十分に確認してください。また、NSPの設定や運用にはAzureの権限管理やネットワークの知識が必要です。

**詳細**:

Azure Event Hubsにおいて、Network Security Perimeter（NSP）サポートが一般提供（GA）となりました。このアップデートの背景には、企業がクラウド上のPaaSリソースに対してより高度なネットワークセキュリティを求めるニーズがあります。従来、Event Hubsのネットワーク制御はIPベースや仮想ネットワークサービスエンドポイントなどに限定されていましたが、NSPの導入により、論理的なネットワーク隔離境界を定義し、パブリックネットワークアクセスを境界ベースのアクセスルールで制御できるようになりました。

具体的な機能として、NSPを利用することで、Event Hubsへのアクセスを組織のセキュリティポリシーに合わせて柔軟に制御できます。NSPは、リソース単位ではなく、ネットワーク境界単位でアクセス制御を行う仕組みです。これにより、Event Hubsを含むPaaSリソースへのパブリックアクセスを許可するかどうか、あるいは特定のネットワークからのみアクセスを許可するかといった設定が可能になります。技術的には、NSPはAzureのネットワークセキュリティ管理機能と連携し、アクセスルールの適用や監査を一元的に行うことができます。

実装方法としては、AzureポータルやAzure CLIを用いてEvent HubsインスタンスにNSPを適用し、必要なアクセスルールを定義します。これにより、組織のセキュリティ境界を明確にし、不要なパブリックアクセスを排除することができます。活用シナリオとしては、金融や医療など高いセキュリティ要件が求められる業界で、Event Hubsを利用したデータストリーム処理やリアルタイム分析の際に、ネットワーク境界を明確に保護する用途が挙げられます。

注意点として、NSPの適用により、従来許可されていたパブリックアクセスや特定IPからのアクセスが制限される場合があります。アクセスルールの設定ミスによるサービス停止リスクや、既存のネットワーク構成との整合性を十分に確認する必要があります。また、NSPはEvent Hubs以外のAzure PaaSサービスとも連携可能であり、Azure StorageやAzure SQL Databaseなど、他のサービスと一貫したセキュリティポリシーを適用することができます。

以上のように、Azure Event HubsのNetwork Security Perimeterサポートは、クラウド上のデータストリーム処理基盤に対して、より強固なネットワークセキュリティを実現するための重要なアップデートです。技術者はNSPの導入により、セキュリティ要件に応じた柔軟なアクセス制御と監査を実現できるようになります。

### 5. Generally Available: Confidential Computing support for Azure Event Hubs Dedicated

**公開日時**: 2026年07月07日 17:33:53 UTC
**リンク**: [Generally Available: Confidential Computing support for Azure Event Hubs Dedicated](https://azure.microsoft.com/updates?id=567212)

**アップデートID**: 567212
**情報源**: Azure Updates API

**カテゴリ**: Launched, Analytics, Event Hubs, Compliance, Security, Services

**要約**:

- 何が更新されたか  
Azure Event Hubs DedicatedでConfidential Computingのサポートが一般提供（GA）されました。

- 主な変更点や新機能  
このアップデートにより、Event Hubs Dedicatedでストリーミングデータを処理する際、ハードウェアベースのTrusted Execution Environment（TEE）を利用して、メモリ上のデータを保護できるようになりました。これにより、処理中のデータの機密性が強化され、セキュリティ要件の高いワークロードにも対応可能です。

- 影響を受ける対象  
Azure Event Hubs Dedicatedを利用する組織やアプリケーションが対象です。特に、機密データを扱う金融、医療、政府などの業界で、データ保護が求められるシナリオに有効です。

- 注意点があれば記載  
Confidential ComputingはDedicated SKUのみでサポートされており、StandardやBasic SKUでは利用できません。既存のシステムで利用する場合は、対応するSKUへの移行が必要です。また、TEEの利用に伴うパフォーマンスやコストへの影響も事前に確認することを推奨します。

**詳細**:

Azure Event Hubs DedicatedにおいてConfidential Computingのサポートが一般提供となりました。本アップデートの背景には、企業や組織がストリーミングデータの処理時におけるセキュリティ要件の高まりがあります。従来、データは保存時や転送時の暗号化が主流でしたが、処理中のデータ（インメモリデータ）については保護が不十分な場合がありました。Confidential Computingは、この課題に対応するため、データがメモリ上で処理されている間も保護することを目的としています。

具体的な機能としては、Azure Event Hubs DedicatedがハードウェアベースのTrusted Execution Environment（TEE）を活用し、ストリーミングデータの処理中にデータの機密性を維持します。TEEは、CPUレベルで隔離された安全な領域を提供し、外部からのアクセスや改ざんを防ぎます。これにより、データがメモリ上で処理されている間も、管理者やクラウドプロバイダーを含む第三者からのアクセスを防ぐことが可能です。

技術的な仕組みとしては、Azure Event Hubs DedicatedのインスタンスがTEE対応のハードウェア上で動作し、データ処理プロセスがその隔離された環境内で実行されます。これにより、ストリーミングデータの受信、処理、転送の各段階で、データの機密性が担保されます。TEEの実装には、Intel SGXなどのハードウェア技術が用いられることが一般的ですが、Azure Event Hubs Dedicatedの具体的なハードウェア構成については公式ドキュメントを参照する必要があります。

活用シナリオとしては、金融、医療、政府機関など高いセキュリティ要件を持つ業界で、リアルタイムデータストリーミングの際に、処理中のデータの機密性を確保したい場合に有効です。例えば、個人情報や機密性の高い取引データをリアルタイムで分析する際に、Confidential Computingによる保護を適用することで、法規制や社内ポリシーへの対応が容易になります。

注意点としては、Confidential Computingの利用にはTEE対応のハードウェアが必要であり、Azure Event Hubs Dedicatedでのみサポートされる点です。StandardやBasicのEvent Hubsでは利用できません。また、TEE環境下での処理にはパフォーマンスやコスト面での影響がある場合があるため、事前に十分な検証が必要です。

関連するAzureサービスとの連携については、Event Hubs Dedicatedは他のAzureサービス（例えばAzure Stream AnalyticsやAzure Functions）と組み合わせて、セキュアなストリーミングデータ処理基盤を構築することが可能です。Confidential Computingによる保護は、これらのサービス間でデータが移動する際にも、処理中のデータの機密性を維持する役割を果たします。
