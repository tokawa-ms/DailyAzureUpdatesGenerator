**要約**:

【何が更新されたか】  
Azure VMにおいて、各ディスク単位でのレジリエンシー（耐障害性）機能がパブリックプレビューとして提供開始されました。

【主な変更点や新機能】  
VMに接続されたマネージドディスクへのアクセスが長時間失われた場合、Azureが自動的にVMを回復します。具体的には、ディスク接続が復旧すると、VMがシャットダウンされ再起動されます。このプロセスはユーザーによる操作を必要とせず、従来のデフォルト動作が維持されます。

【影響を受ける対象】  
Azure上でマネージドディスクを利用している仮想マシン（VM）が対象となります。ディスク障害時の自動回復機能を活用することで、VMの可用性向上が期待できます。

【注意点】  
この機能は現在パブリックプレビュー段階です。運用環境での利用には十分な検証が必要です。また、VMのシャットダウンと再起動が発生するため、一時的なサービス停止が生じる可能性があります。ユーザーによる追加操作は不要ですが、システム全体の可用性設計に留意してください。

**詳細**:

本アップデート「Public Preview: Per-disk resiliency for Azure VMs」は、Azure仮想マシン（VM）に接続されたマネージドディスクの可用性向上を目的とした機能のパブリックプレビュー開始を示しています。従来、Azure VMが接続しているマネージドディスクへのアクセスが長時間にわたり失われた場合、ユーザー側での対応が必要となるケースがありましたが、本機能により、Azureが自動的にVMの復旧処理を実施するようになりました。

具体的には、VMがアタッチしているマネージドディスクのいずれかに長時間アクセスできない状態が発生した場合、Azureプラットフォームが自動的に当該VMをシャットダウンし、ディスク接続が復旧したタイミングで再度VMを起動します。この一連の復旧プロセスは完全に自動化されており、ユーザーによる手動操作や追加設定は不要です。これにより、ディスク障害時のサービスダウンタイムを最小限に抑えつつ、運用負荷の軽減が期待できます。

技術的な仕組みとしては、Azureの管理基盤がVMとマネージドディスク間の接続状態を常時監視し、一定期間以上ディスクへのアクセスが失われた場合に自動的にVMのシャットダウンおよび再起動処理をトリガーします。復旧後は、元の状態でVMが再稼働するため、アプリケーションやサービスの継続性が確保されます。この動作はデフォルトで有効化されており、既存のVMにも適用されます。

活用シナリオとしては、ストレージ障害や一時的なネットワーク断などによりディスクへのアクセスが失われた場合でも、迅速な自動復旧が行われるため、ミッションクリティカルなシステムや高可用性が求められる業務システムにおいて有効です。また、運用担当者が常時監視しなくても、Azure側で自律的に復旧処理が行われるため、運用コストの削減にも寄与します。

注意点としては、本機能はディスク接続の復旧後にVMが自動的に再起動されることから、再起動時に一時ディスクデータが失われる可能性や、アプリケーション側での再起動耐性が求められる場合があります。また、詳細な復旧条件やタイミングについては、Azure公式ドキュメントでの確認が推奨されます。

本機能はAzure Virtual MachinesおよびAzure Managed Disksと密接に連携して動作します。他の可用性向上機能（例：Availability SetsやAvailability Zones）と組み合わせることで、より堅牢なシステム設計が可能となります。今後の正式リリースに向けて、パブリックプレビュー期間中に実運用環境での検証を進めることが推奨されます。
