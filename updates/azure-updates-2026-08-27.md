### 1. Generally Available: Azure Bastion shareable link expiration 

**公開日時**: 2026年08月26日 16:57:56 UTC
**リンク**: [Generally Available: Azure Bastion shareable link expiration ](https://azure.microsoft.com/updates?id=570020)

**アップデートID**: 570020
**情報源**: Azure Updates API

**カテゴリ**: Launched, Networking, Security, Azure Bastion, Features

**要約**:

- 何が更新されたか  
Azure Bastionの「共有リンクの有効期限設定」機能が一般提供（GA）となりました。

- 主な変更点や新機能  
管理者はAzure Bastionで共有リンクを作成する際に、有効期限（日時）を指定できるようになりました。設定された有効期限を過ぎると、そのリンクを利用しての接続はできなくなります。

- 影響を受ける対象  
Azure Bastionを利用している管理者および、共有リンク経由で仮想マシンへアクセスするユーザーが対象です。特に一時的なアクセス権限の付与やセキュリティ強化を求める運用に有用です。

- 注意点があれば記載  
有効期限を過ぎた共有リンクは利用不可となるため、アクセスが必要な期間を正確に設定する必要があります。リンクの有効期限管理を徹底し、不要なアクセス権限の残存を防ぐことが推奨されます。

**詳細**:

Azure Bastionの「shareable link expiration」機能が一般提供（GA）となりました。本アップデートの背景には、セキュリティ強化と運用効率向上のニーズがあります。従来、Azure Bastionを利用してリモート接続を行う際、管理者が生成した共有リンクは明示的な有効期限設定ができず、リンクの管理やアクセス制御に課題がありました。今回のアップデートにより、管理者は共有リンク作成時に有効期限（日時）を指定できるようになりました。これにより、リンクの利用可能期間を厳密に制御でき、不要なアクセスやリンクの悪用リスクを低減できます。

具体的な機能としては、Azure Bastionの管理画面やAPIを通じて共有リンクを生成する際、リンクの有効期限を設定できます。設定した期限を過ぎると、そのリンク経由での接続は自動的に無効化され、アクセスが拒否されます。技術的な実装としては、リンク生成時に有効期限情報がメタデータとして付与され、Azure Bastion側で期限チェックが行われます。期限切れの場合、認証や接続要求は拒否される仕組みです。

この機能は、例えば一時的なリモート作業や外部委託先への限定的なアクセス許可など、期間限定で安全にリソースを公開したい場合に有効です。管理者はリンクの有効期限を設定することで、意図しない長期的なアクセスを防ぎ、運用後のリンク管理負担を軽減できます。

注意点として、リンクの有効期限を過ぎると再利用や延長はできず、新たにリンクを生成する必要があります。また、リンクの有効期限設定は管理者が明示的に行う必要があり、誤って長期間の期限を設定した場合はその間アクセスが許可され続けるため、設定時には十分な注意が必要です。

Azure BastionはAzure Virtual Network内の仮想マシンへの安全なRDP/SSH接続を提供するサービスであり、今回の機能追加は他のAzureセキュリティサービスやID管理機能と連携して利用することで、より高度なアクセス制御や監査が可能となります。全体として、Azure Bastionの運用管理とセキュリティを強化する実用的なアップデートです。

【何が更新されたか】

【主な変更点や新機能】  
新規のAzure Bastionデプロイメントにおいて、IPv4およびIPv6の両方のパブリックIPアドレスを設定できるようになりました。これにより、IPv6アドレスを用いた接続が可能となり、ネットワークの柔軟性と将来性が向上します。

【影響を受ける対象】

**詳細**:

Azure BastionにおけるIPv4およびIPv6デュアルスタック構成のサポートがパブリックプレビューとして提供開始されました。本アップデートの背景には、クラウド環境におけるIPv6対応の需要増加や、グローバルなIPアドレス枯渇問題への対応が挙げられます。これにより、Azure Bastionを利用する際に、従来のIPv4だけでなくIPv6にも対応したネットワーク構成が可能となり、より柔軟かつ将来性のあるインフラ設計が実現できます。

具体的な機能としては、新規作成するAzure Bastionのデプロイメント時に、IPv4とIPv6の両方のパブリックIPアドレスを割り当てることが可能となります。これにより、ユーザーはIPv4/IPv6どちらのプロトコルを利用してもBastion経由で仮想マシンへの安全なリモートアクセスを確保できます。IPv6は、ユーザーとAzure Bastion間の接続に対応しており、今後のネットワーク拡張やグローバルなアクセス要件にも柔軟に対応できます。

技術的な仕組みとしては、Azure Bastionのデプロイ時に、Azure PortalやARMテンプレートを用いてIPv4とIPv6のパブリックIPリソースを同時に作成・割り当てることができます。これにより、Bastionホストは両方のIPアドレスで待ち受け、ユーザーは自身のネットワーク環境に応じて適切なプロトコルで接続可能です。Azureのネットワークインフラは、IPv6アドレスの割り当てやルーティングにも対応しており、既存のセキュリティグループやルール設定もIPv6に拡張できます。

活用シナリオとしては、IPv6対応が求められる企業や、グローバル展開を行うサービスでのリモートアクセス環境の構築、またはIPv4アドレス枯渇対策としてのデュアルスタック運用が考えられます。例えば、海外拠点やモバイルネットワークからのアクセスにおいてIPv6のみ利用可能な環境でも、Azure Bastionを介して安全な管理アクセスを確保できます。

注意点として、現時点ではパブリックプレビュー段階であるため、本番環境での利用には慎重な検証が必要です。また、IPv6のサポート範囲はユーザーとAzure Bastion間の接続に限定されており、仮想マシンや他のAzureリソースとの接続に関しては、今後のアップデートや公式ドキュメントの確認が必要です。

関連するAzureサービスとの連携については、Azure Virtual NetworkやパブリックIPリソース、セキュリティグループなど、既存のネットワーク構成要素と組み合わせて運用可能です。これにより、Azure Bastionを中心とした安全なリモートアクセス環境を、IPv4/IPv6両対応で設計・運用することができます。

**要約**:

- 何が更新されたか  
Azure BastionとAzure Kubernetes Service（AKS）の統合が一般提供（GA）となりました。

- 主な変更点や新機能  
このアップデートにより、ユーザーはAzure Bastionを経由してローカルマシンからAKSクラスターのAPIサーバーへセキュアなトンネル接続を確立できるようになりました。これにより、標準的なkubectlなどのKubernetesクライアントツールを安全に利用してAKSクラスターを操作できます。

- 影響を受ける対象  
AKSクラスターを利用しているAzureユーザーや、セキュアな管理アクセスを必要とする運用担当者・開発者が対象です。特に、パブリックIPを公開せずにAKSクラスターへアクセスしたい場合に有用です。

Azure Bastionの利用には追加のコストが発生します。また、事前にBastionのセットアップと必要なネットワーク構成が求められます。既存のアクセス制御やセキュリティポリシーとの整合性も確認してください。

**詳細**:

Azure BastionとAzure Kubernetes Service（AKS）の統合が一般提供（GA）となりました。このアップデートの背景には、AKSクラスタへの安全なアクセス手段の強化という目的があります。従来、AKSクラスタのAPIサーバーへアクセスする際には、パブリックIPやVPN、Jump Boxなどを利用する必要があり、セキュリティや運用の複雑さが課題となっていました。今回のAzure Bastionとの統合により、ユーザーはローカルマシンからAzure Bastion経由でAKSクラスタのAPIサーバーへ安全なトンネル接続を確立できるようになりました。

具体的な機能としては、Azure Bastionを利用してAKSクラスタのAPIサーバーに対してセキュアなアクセスを提供します。ユーザーは標準的なkubectlコマンドを用いて、ローカル環境からAKSクラスタの管理操作を実行できます。Azure Bastionは、仮想マシンへのRDPやSSH接続だけでなく、AKSクラスタへのAPIアクセス用のトンネルもサポートするようになった点が大きな変更です。

技術的な仕組みとしては、Azure BastionがAKSクラスタのAPIサーバーへのトンネルを仲介する役割を担います。ユーザーはAzure Bastionを経由してAPIサーバーに接続するため、クラスタのAPIエンドポイントをインターネットに公開する必要がありません。これにより、ネットワークセキュリティが向上し、管理者は最小限の公開範囲でクラスタの運用が可能となります。

活用シナリオとしては、企業内のセキュリティポリシーに従い、AKSクラスタのAPIエンドポイントをパブリックにせず、Azure Bastion経由でのみ管理アクセスを許可するケースが挙げられます。例えば、開発者や運用担当者が自分のローカルマシンからkubectlを用いてクラスタ管理を行う際、Azure Bastionを経由することで安全な接続が担保されます。

注意点としては、Azure Bastionの利用には追加のコストが発生すること、またAKSクラスタやBastionの設定が適切に行われている必要があることが挙げられます。さらに、Azure Bastionのサポートするリージョンや機能範囲にも制限がある場合があるため、事前に公式ドキュメントで対応状況を確認することが重要です。

関連するAzureサービスとしては、Azure Bastion自体が仮想ネットワーク内のセキュアなリモートアクセスを提供するサービスであり、AKSとの連携によってクラスタ管理のセキュリティが大幅に向上します。その他、Azure Active Directoryやネットワークセキュリティグループ（NSG）との組み合わせによるアクセス制御も可能です。今回のアップデートは、Azure上でKubernetesクラスタを安全かつ効率的に運用するための重要な機能強化となっています。
